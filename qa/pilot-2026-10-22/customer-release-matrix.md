## Three fresh novice-week scenarios — proposed, provider-free

These are **new acceptance plans, not executed transcripts or observed live AI output**. Use synthetic accounts and an injected trusted clock/account timezone. For assistant turns use explicitly scripted tool outputs, captured SMS transport and fake Calendar/catalog adapters; never call real services. End each day by rereading durable state. A second synthetic account must remain empty/private. A browser variant should use local synthetic sessions prepared by root, not customer logins.

### 1. Maya: a project, interruptions and a recovered next step

- **Days 1–2:** Skip optional personalization. Capture “Ask studio about Saturday access” with a long detail; convert to “Call studio,” choose five minutes, save/reload, then repeat conversion from a scripted shared conversation. Assert one task and unchanged thought. Open exact task, start, pause and reload.
- **Days 3–4:** Resume and complete it; undo once. Ask for “outline project Friday at 3 PM and remind me Friday at 2 PM.” Assert distinct task schedule/reminder with intended local dates, then simulate a lost response and retry: one task/reminder/job. A deadline is never silently treated as a text request.
- **Days 5–7:** Captured reminder arrives; reschedule through a linked reply while an unrelated message intervenes. Complete task, inspect the still-explicit reminder policy and cancel any remaining occurrence. Remove the first linked task and revisit its thought: explicit removed state, no recreation. Report a synthetic problem and retain its receipt.

### 2. Luis: dinner planning that survives a changed week

- **Days 1–2:** Save a two-serving recipe; plan four portions for dinner. Assert doubled compatible quantities, source links and a separate manually added grocery. Change to two portions, retry the save and reload: one derived row per compatible ingredient, manual grocery intact.
- **Days 3–4:** Swap dinner recipe and turn shopping off/on. Mark rice purchased, then explicitly record 100 g pantry stock. Assert purchase alone did not add stock; known stock reduces matching need; unknown pantry amount does not guess. Ingredients/plural labels remain readable.
- **Days 5–7:** Manually log the portion actually eaten with one unknown nutrient. Assert no automatic eaten-food record from meal planning and totals honestly partial. Copy food to another date, correct it, then retrieve the older day. Calendar is disconnected and catalog/camera denied throughout; core food work still succeeds.

### 3. Priya: routines, quiet hours and returning after a break

- **Days 1–2:** Synthetic account starts with default timezone; complete explicit local-time setup before scheduling. Save a three-step morning routine, reorder one step and retain its identity/progress. Request a weekday reminder and inspect saved recurrence even if dashboard cadence label is not yet implemented.
- **Days 3–4:** Captured delivery plus DONE/snooze/cancel uses the intended reminder, across a web/text-style scripted interruption. Test a quiet-hours boundary and a busy fake Calendar interval against the correct deterministic gates; disabling proactive check-ins does not silently erase an explicit requested reminder.
- **Days 5–7:** STOP, then “leave me alone,” website reconsent and invitation changes retain suppression; no welcome/resume/coaching job escapes. Explicit START is required to opt in. Return through a new synthetic browser session, inspect the same records, hide progress numbers and remove an incorrect memory without deleting history. One optional saved workout/log demonstrates that scheduled task completion is separate.
