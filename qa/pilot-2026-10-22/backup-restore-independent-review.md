# Independent local backup/restore review

Reviewed 2026-10-22 by `w2_reminder_clarity`, who did not author the restore script. Scope: `scripts/pilot-restore-check.ts`, its configuration/migration helpers, relevant encryption/feedback/accounting implementations, and `backup-restore.md/json`. No production database, populated environment file, provider, cluster restart, or application worker was used. Root owns the final integrated check.

## Finding corrected before execution

The initial script sanitized the dump/restore subprocess environment but Node PostgreSQL and pg-boss clients could still inherit `PGOPTIONS`, password/SSL settings and password-file fallback. Inspection of the installed `pg/lib/connection-parameters.js` confirmed those fallbacks despite an explicit connection string. The author corrected this before the independent run: the standalone script deletes inherited `PG*` variables by name before constructing any client, then sets `PGPASSFILE=NUL`. No inherited values were inspected or printed. The prose now references the latest JSON timings rather than retaining stale first-run numbers.

## Safety and comparison review

- `pilotLoadConfig([])` validates every URL component against the exact fixed `127.0.0.1:55437/tempo_ui_release` administration fixture. The script accepts no arguments. The administration connection only creates/drops databases; dump and restore use newly generated source/target names. Every create/drop checks equality with this run's random names, and SQL identifiers are quoted. Cleanup iterates only databases successfully created by this run. Success evidence requires both removals.
- PostgreSQL tools use the known PG17 runtime and explicit loopback/port/user/database arguments, no password prompt, a minimal environment, bounded output and a timeout. `pg_dump --version` independently reported PostgreSQL 17.11. The archive remains in memory and is zeroed after successful verification; neither its bytes nor ephemeral encryption key are written to the evidence file. Only the archive hash/size and summary assertions are emitted.
- Source and restored snapshots compare sorted row JSON for every table in `public`, `drizzle` and `pgboss`, plus constraint definitions, index definitions, semantic enum order and sequence state. This covers 55 tables, with 13 populated table entries. Most tables are empty synthetic-schema coverage, not populated production-data coverage. The two pg-boss parent rows and two common-partition rows represent the same two jobs, as the report explains.
- The source seeds three application action states and real pg-boss created/completed jobs linked by IDs. Snapshot equality proves these durable records survived; it does not run an application worker or prove post-restore delivery/retry execution.
- Both restored calendar token fields and feedback detail decrypt with the same ephemeral key; an unrelated key fails authenticated decryption. Feedback replay returns the original receipt. Migrator rerun preserves the complete snapshot. Explicit check, foreign-key and uniqueness violations are rejected.
- Two accounting attempts are seeded, one settled and one uncertain. A rolled-back restored account deletion checks both attempt account references become null while the global outstanding commitment stays exactly 100 microdollars and one call. A final full snapshot equals the original. This supports preserved unresolved debt, not a new provider reconciliation or rollover claim.
